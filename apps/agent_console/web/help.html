通语使用指南

本指南对应当前本机运行的通语客服平台。先按下面的步骤完成一次客户发消息、客服接待和回复，再配置自动回复与系统接入。

1. 打开系统

客服工作台：打开客服工作台；平台运营：打开平台后台；使用指南。

客户聊天与 App WebView 地址：登录后进入「接入 → 接入入口」选择自己的入口并复制地址，不要沿用其他企业的入口标识。

这些地址用于这台电脑上的本地测试。手机或其他公司的系统接入时，应换成可以访问的服务器域名；手机上的 127.0.0.1 指向手机自身。

2. 选择正确的登录入口

后台提供两种登录方式。平台账号必须选择「平台管理员登录」；企业账号必须选择「客服工作台登录」。入口选错会提示账号或密码错误。

账号登录入口用途
platform平台管理员登录开通企业、创建账号、管理企业服务配置
supervisor客服工作台登录客服主管，管理企业配置、成员、渠道与报表
agent客服工作台登录日常接待客户

上表用户名仅为角色示例。企业标识、实际账号和初始密码由平台管理员提供，不写入公开说明。登录后可在个人设置中修改密码。

3. 先完成一次聊天

1. 登录客服工作台，将个人接待状态切换为「在线」。

2. 在「企业管理 → 团队成员」中确认该客服已分配到「在线客服」入口。主管或客服主管可以编辑成员的入口分配。

3. 打开上面的客户聊天入口，发送一条测试消息。

4. 回到「收件箱」，查看「待接待」或「全部」；如果会话未分配，先接待会话。

5. 在会话中回复，客户页面应实时显示回复。

6. 接待结束后将会话标记为已解决，需要再次查看时开启已解决会话筛选。

聊天支持文字、图片和文件；更多操作包括引用回复、表情、消息操作以及客服内部备注。内部备注仅客服可见。语音录制依赖浏览器麦克风权限，目前内置浏览器未完成真实录音验收，不能据此认定录音可用。

4. 给其他企业开通账号

1. 使用平台账号登录，点击「开通企业与账号」。

2. 填写企业名称、企业标识和客服主管的用户名、密码，选择服务配置并提交。

3. 创建成功后保存系统显示的企业标识、登录信息和聊天入口。

4. 进入该企业详情，使用「建立账户」创建客服主管或客服坐席账号。

5. 让客服主管登录工作台，在团队成员中分配客服入口，并让客服上线。

当前版本的新账号由平台管理员创建；企业后台用于编辑已有成员及分配入口。创建失败时弹窗保留填写内容，在弹窗内提示错误，修改后可以重新提交。可建成员数取决于该企业当前套餐和席位配置，需要更多成员时联系平台管理员调整。

5. 配置自动回复

打开「自动回复」，先选择需要配置的客服入口。各入口的配置独立。

- 关键词回复：添加匹配词、回复内容、匹配方式和优先级。

- 打开客服回复：设置客户打开聊天时看到的欢迎内容。

- 收到消息回复：设置收到客户消息后的通用回复。

- 系统客服回复：设置系统回复和离线提示。

- 智能引语：设置可点击的常见问题。

- 智能引流：设置快捷跳转入口。

- 智能菜单：配置回复、链接或转人工操作。

- 转人工客服：配置转人工规则及提示。

- 自动回复设置：启用自动回复，调整回复间隔和人工接待后的机器人行为。

每次修改后保存。若保存了规则却没有回复，先检查「自动回复设置」是否启用、是否配置了正确入口，以及会话是否已进入人工接待。这里的引导和规则功能不等于已接入大模型；真实 AI 服务仍需配置模型提供商。

6. 配置网页、H5 和 App 渠道

进入「渠道管理」。

- H5/App 渠道设置：修改窗口名称、服务说明，复制网页脚本、H5 地址和 App WebView 地址。

- 渠道客服：选择该入口允许接待的成员。

- 快捷方式：设置聊天中的快捷入口。

- 图文模板：设置欢迎图文和行动按钮。

- 自定义菜单：设置客户聊天底部菜单，与智能菜单共享配置。

- 用户消息列表：查看客户会话及历史消息。

当前先支持网页、H5 和 App WebView。微信等外部渠道尚未接入；原生 Android/iOS 设备上的完整功能还需要单独验收。

7. 如何接入别人的系统，Token 怎么用

匿名客户接入

在「应用接入」或「渠道管理」复制生成的嵌入脚本，放到对方网站中。匿名客户只需要服务地址和入口标识，不需要将服务端密钥交给浏览器。

<script>

window.RelayDeskSettings = {

  endpoint: 'http://127.0.0.1:8080',

  inboxKey: '<从接入入口复制的 inboxKey>'

};

</script>

<script src="http://127.0.0.1:8080/widget.js"></script>

H5 可以直接打开聊天链接；App 可用 WebView 加载渠道设置中复制的 App 地址。实际部署时替换上面的本机地址。

对接已有登录用户

1. 在「应用接入 → 服务端密钥」创建具有对应入口权限的密钥。

2. 对方系统的后端根据自己的登录用户，调用 `POST /api/v1/open/visitor-identity`。

3. 请求头使用 `X-RelayDesk-Key`；请求体提供 `inboxKey`、真实用户的 `externalId` 和 `displayName`。

4. 将响应中的 `identityToken` 和 `inboxKey` 返回给对方前端。

5. 前端把 `identityToken` 加到 `window.RelayDeskSettings`，再加载组件。

服务端密钥保存在对方后端。`identityToken` 是短期客户身份票据，有效期 5 分钟；聊天组件会自行换取会话和实时连接凭证。后台登录 token、服务端密钥和客户身份票据用途不同，不能互换。不要把身份票据拼进 H5 链接。

完整请求、iframe 身份通信和事件回调配置见项目中的 `docs/saas-onboarding.md`、`docs/integrations.md`、`docs/open-api.md`。

9. 本机服务如何重新启动

当前使用 Docker 容器 `relaydesk-local` 和数据库容器 `deploy-postgres-1`。打开 Docker Desktop 后，在 PowerShell 执行：

docker start deploy-postgres-1

docker start relaydesk-local

Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing

健康检查返回 200 后，打开后台地址。首次安装和服务器部署请另看 README 与部署文档；这里的启动命令用于当前已经配置好的本机环境。

群聊怎么使用

后台新增「群聊 → 建群」，可以选择内部协作群或客户服务群。创建后点击群成员添加同企业同事；客户服务群点击邀请客户，复制24小时有效的邀请链接，客户填写称呼即可加入，不需要邮箱或验证码。

群主可修改名称、公告、移除成员、归档；群成员可发送文字、搜索消息并实时接收回复。内部群不允许客户加入。

群聊支持文字、表情字符及群语音/视频通话，详情见下文。图片文件与单独的 @ 提醒需按实际版本确认。

群聊互动与通话

客服在「群聊」里建内部协作群或客户服务群。自己的消息下方可撤回；更多菜单可修改群昵称，群主可解散群聊。客户在群页面「设置」中修改昵称。

点群聊电话图标或客户页面「通话」，选择群成员发起一对一语音。来电可接听、拒接；通话中可静音、挂断。只有你点击呼叫或接听才会请求麦克风。

解散后停止发送和通话、邀请失效，但历史仍可查看。通话上线需要 HTTPS，跨公网稳定连接需要自有 STUN/TURN；App WebView 需要宿主授权麦克风。

群语音与群视频

在群聊右上角点「通话」，选择群语音或群视频，每场最多 6 人。其他成员通过同群中的「加入通话」进入，客服工作台也会提示新发起的群通话。

视频通话可取消勾选「开启我的摄像头」，仅语音加入；点击「开启摄像头」时才申请权限。支持静音、开关摄像头、退出，发起人或群主可结束全场。

平台管理员入口：平台运营后台；客服入口：客服工作台。各标签页分别记住入口，有效平台登录可直接恢复后台。

本机三人真实群语音已验收；视频房间关闭摄像头加入已验收，真实视频画面按用户要求未启用、未验收。公网需自有 STUN/TURN，物理手机和原生 App 未实机验收。

新消息提醒、未读与回执

客服在「设置」底部开启或关闭提示音，点击「测试提示音」确认浏览器可以播放。桌面通知需要主动授权；不支持或拒绝时继续使用提示音和未读角标。网页关闭后不再提醒。

只有在前台查看会话时才自动已读；设置页、隐藏页面、收起的聊天窗和查看历史消息不会清空最新未读。已读按最高消息序号推进，重复和较早的回执不会回退。

接入方后端通过服务端 API Key 调用以下接口，密钥不能放到客户前端：

GET /api/v1/open/unread
GET /api/v1/open/conversations/{id}/receipts
POST /api/v1/open/conversations/{id}/delivered
POST /api/v1/open/conversations/{id}/read
X-RelayDesk-Key: <server-api-key>
Content-Type: application/json

{"readerType":"VISITOR","readerId":"<visitor-uuid>","sequence":12}

查询需 read 权限，上报需 write 权限，专业版及以上开放 API 可用。readerId 必须属于该会话客户或企业活跃客服，sequence 必须大于零。unread 是企业汇总；单客户应按自己的会话汇总。消息序号不能直接当作未读条数。

在「接入 → 事件回调」勾选 conversation.read、conversation.delivered；已有回调需要补选。正文包含 conversationId、readerType、readerId、sequence；验签采用 HMAC-SHA256(secret, timestamp + "." + 原始正文)，签名头值为 sha256=<十六进制签名>，请求头为 X-RelayDesk-Timestamp、X-RelayDesk-Signature，投递 ID 为 X-RelayDesk-Delivery。校验时间窗口、按投递 ID 去重、持久化最大 sequence 后返回 2xx，失败会重试。

完整请求与示例见项目 docs/open-api.md。回调表单提交失败会保留输入，可修正后继续保存。
