# 独立部署与运维指南

适用：为一个运营方部署一套通语多租户平台。复核日期：2026-10-23。本说明按现有源码和运维材料整理；不是已经完成干净服务器验收的通用安装器。

## 部署单位与前提

每个独立运营方使用独立域名、应用实例、数据库、附件存储和安全密钥。该运营方下的企业通过后台开租户，不逐个重复部署。先书面确认软件运营许可、支持范围、基础设施负责人、资源费用、备份恢复目标和服务级别。

准备能支持 Docker/Compose 的 Linux 主机或等效托管环境、PostgreSQL、持久附件存储、HTTPS 域名及允许 WebSocket 的反向代理。服务器规格通过实际会话、消息与附件负载确定；本项目未提供可承诺的通用最小规格或并发容量。

## 构建发行版本

1. 固定源码版本，记录构建工具版本和所有未提交改动，执行针对本次版本的检查。
2. 在 `packages/widget` 按锁文件安装依赖并执行 `npm test`、`npm run build`，生成 `dist/widget.js`。
3. 用兼容当前 HTML 引导脚本的 Flutter SDK 执行 `scripts/build-console.ps1`；检查完整 Web 目录、PWA 资源和群聊根资源，不能只复制 index.html。
4. 从项目根目录构建固定版本镜像。当前 Dockerfile 编译 Go，但 Widget/Flutter 是预构建输入，不在镜像构建时运行 npm/Flutter。
5. 将镜像 ID/digest、Web 资源哈希、迁移清单、架构、版本和配置模板归档。客户取得预构建镜像后不需要 Go/Flutter 工具链；当前 `scripts/pack-isolated-deploy.ps1` 仍是源码加预构建 Web 的部署包，不应冒充成品镜像发行包。

独立镜像仓库、离线镜像导出与通用安装器尚需工程化。`deploy/docker-compose.yml` 用于开发；`deploy/isolated` 含特定服务器地址、端口和演示默认值，不作为对外安装模板原样使用。

## 必填运行配置

- `DATABASE_URL`：专属数据库连接；数据库不暴露公网，TLS 按网络部署要求设置。
- `PUBLIC_BASE_URL`：实际 HTTPS 根地址，不含末尾斜杠。
- `WIDGET_TOKEN_SECRET`：每套平台单独生成、至少 32 字符的高强度随机秘密。更换会使签名相关身份失效，轮换须安排会话影响。
- `PLATFORM_ADMIN_EMAIL` 与 `PLATFORM_ADMIN_PASSWORD`：首次创建平台管理员。已有账号不会由重启或环境变量覆盖；临时密码安全传递后由持有人修改。
- `DEMO_ENABLED=false`：不创建演示企业、演示账号或演示知识。
- `ALLOWED_ORIGINS`：允许的真实站点 Origin，逗号分隔；`FRAME_ANCESTORS`：CSP 来源列表，输入值同样逗号分隔（写入 CSP 响应时由空格连接）。生产精确列出平台和宿主源。
- `STORAGE_DRIVER=local` 与挂载持久卷的 `STORAGE_LOCAL_DIR`，或 `STORAGE_DRIVER=s3` 及 bucket、region、endpoint、访问凭证、path style。多副本需共享附件后端。
- `DATABASE_MAX_CONNS`、`MAX_WS_CONNECTIONS`：按数据库配额、内存和文件描述符设置，不把默认上限当作负载证明。
- AI 可选：`AI_PROVIDER`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 及 Embedding 配置。没有真实生成测试不能认定 AI 可用。
- RTC 可选：`TONGYU_RTC_ICE_SERVERS`。跨 NAT 通话需要实际 STUN/TURN 及设备测试；WebRTC 最多六人 mesh 不等于大型会议服务。

环境配置不随资料包发出，不写入公共 Git；日志和代理应对登录、身份票据、WebSocket query token 和 API Key 脱敏。

## 初始化与代理

应用启动连接数据库，串行执行未执行过的内嵌迁移，然后按配置建立首个平台管理员。启动失败要保留并定位错误；不能以容器存在认定初始化成功。数据库迁移修改结构，生产更新前审查兼容性并备份。

反向代理提供 HTTPS、WebSocket Upgrade、合理的上传与空闲超时；`/` 由官网处理，不强制跳转客服工作台；保留 `/widget.js`、`/h5/`、`/console/`、`/api/` 和 `/ws/` 路由。证书签发、续期和同机其他业务保护由运维方负责。

`GET /health` 主要验证数据库存活；`GET /ready` 报告连接、存储类型和 AI provider 等配置，不会完整验证对象存储写入、模型实际生成或客户身份链路。`GET /api/v1/meta` 可查看基本能力。指标接口应置于受控监控网络。

## 首次安装验收

以新建测试企业验证平台登录、企业/成员开通、套餐与有效期、跨企业拒绝、入口权限、访客消息、客服接待、回复、断线补拉、附件下载和进程重启后持久性。登录接入须通过目标宿主后端，不能用匿名演示替代真实身份。记录域名、软件构建、时间和验证层级。

## 升级与回滚

升级前导出数据库、附件、运行配置和镜像标识，检查新迁移与旧版本兼容。保留完整旧镜像再替换应用；升级后复测登录、消息、附件与接口兼容。自动执行迁移不等于自动安全回滚。

只有旧应用兼容当前数据库时才能仅回退镜像。涉及数据结构回退时先停止写入、保留现场、明确可接受的数据丢失范围，再按恢复方案执行。不要在应用持续写入时恢复旧数据库。

## 备份恢复与日常运营

数据库使用可验证的逻辑备份或托管快照；附件、加密配置与必要元数据配套备份，至少保留一份异地/独立访问控制副本。制定频次、保留期、加密和密钥保管责任。定期在隔离恢复环境验证数据库、附件、身份和完整业务；恢复可用的证据不能由备份文件存在代替。

监控进程、数据库连接、磁盘、备份、证书、消息延迟、Webhook 失败和 AI 错误。套餐权限、手工额度与服务有效期见 [平台 API](platform-api.md)；自动付款续费尚未实现。
