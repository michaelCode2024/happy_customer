# 人工接单与超时分配

访客点击转人工、菜单转人工或 AI 转人工时，机器人暂停。访客依次看到真实的状态消息：

1. 正在为您转接人工客服。
2. 已分配给客服「姓名」，等待客服接待。没有符合条件的客服时显示排队。
3. 客服在工作台点击“确认接单”后，才显示“客服已接入”。

这些状态由实际操作触发，没有人为延迟。未确认接单的客服不能向客户发送回复；内部备注仍可使用。

## 设置与路由

客服主管在“客服入口 → 配置”设置“接单超时（秒）”，默认 60 秒，可设置 10～600 秒。设置影响之后的新分配，已经分配的会话按原期限执行。

自动分配仍使用入口配置的优先空闲、轮流或指定成员策略，候选成员必须在线、启用、有入口权限且未超过并发接待额度。待确认会话也占用并发额度。

超时后释放原分配，并跳过本会话已超时的客服重新分配。指定成员超时后，使用优先空闲策略寻找其他成员。候选人用尽时保留排队，后续有其他合适成员上线可再次分配，客服也可主动领取。机器人在整个等待过程中保持暂停。

客服转派会话后，新的客服也需要确认接单。已接入的会话不会因接单超时被重新分配。

## 接口与兼容

`POST /api/v1/console/conversations/{id}/claim`：领取未分配会话，或确认分配给自己的会话。重复确认成功但不重复发送接入提示。分配已过期或归属其他客服时返回 409。

会话详情及列表新增 `acceptedAt` 和 `assignmentExpiresAt`。有 `assigneeId`、无 `acceptedAt` 且有 `assignmentExpiresAt` 表示已分配待确认；有 `acceptedAt` 表示已接入。接待状态独立于原有 OPEN、PENDING、RESOLVED 会话状态。

状态消息携带 `metadata.receptionState`，值为 TRANSFERRING、QUEUED、ASSIGNED、ACCEPTED。服务端发送 `conversation.handoff` 实时事件，客户端刷新列表及详情；断线后读取消息历史也能恢复状态。

升级时执行数据库迁移 `018_reception_acceptance.sql`。已有已分配会话保留接待状态，不强制重新确认；新分配执行确认流程。持久通知在服务重启后继续投递，防止分配或确认成功后遗漏客户提示。
