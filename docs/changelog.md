# 变更记录与版本策略

版本 **v1** · 更新日期 **2026-11-02** · 适用服务端 **TongYu 主线**

本页说明通语开放接口的版本规则、弃用流程和每次变更的内容。接入方应按本页判断升级影响，不要只依赖文档正文的措辞变化。

## 版本规则

| 项 | 规则 |
| --- | --- |
| 版本号 | `v主版本`，当前为 **v1**；主版本号出现在文档页首与 `X-TongYu-Key` 所属企业的开通资料中 |
| 向后兼容 | 同一主版本内不删除字段、不改变已有字段语义、不把可选参数改为必填 |
| 允许的新增 | 新增可选请求字段、新增响应字段、新增枚举值、新增接口、放宽校验 |
| 破坏性变更 | 提升主版本，新旧版本并行至少 90 天 |
| 预览能力 | 文档标注「预览」的接口或字段可能变更，不建议直接用于生产 |

新增响应字段是允许的变更，因此**客户端必须忽略未知字段**。把响应反序列化成固定结构的语言（如 Go 的 `struct`、Java 的 `record`）时，请确认未开启「未知字段报错」。

## 弃用流程

1. 在文档对应位置标注「已弃用」，并给出替代接口或字段。
2. 在本页变更记录中登记弃用日期与计划下线日期。
3. 弃用期不少于 **90 天**；期间旧接口继续按原语义工作，不做行为调整。
4. 到期后旧接口返回 `410`，`message` 指向替代方案。

> 当前版本**没有**在响应头提供 `Deprecation` / `Sunset` 信号，弃用只通过本页与文档标注告知。依赖自动化探测的接入方请改为定期抓取本页。

## 升级检查清单

主版本升级前，建议按以下顺序自查：

1. 对比新旧规范的 `paths` 与 `components.schemas`，列出自己实际调用的接口。
2. 检查请求是否发送了即将移除的字段——未知字段会被拒绝并返回 `400`，不是静默忽略。
3. 检查是否依赖了即将改变语义的响应字段，尤其是 `agentUnread`、`visitorUnread` 这类计数。
4. 在测试企业上跑一遍完整链路：签发票据 → 建会话 → 收发消息 → 上报回执 → 接收 Webhook。
5. 确认 Webhook 接收端仍能通过验签，事件正文结构变化时先兼容新旧两种。

## 反馈渠道

接口行为与本文不符时，请带上请求 ID、时间点、完整的请求与响应（脱敏后）联系技术支持。仅凭错误文案无法定位问题——程序判断请使用 `status` 与 `code`。
