# 第三方网站与 App 群聊接入

第三方继续使用自己的账号和用户 ID，不需要为用户创建通语客服账号。通语仅保存参与聊天所需的 `externalId`、昵称、访客映射和群成员关系。企业和客服入口由平台开通一次，第三方用户日常建群、入群及管理均在自己的网站或 App 完成。

## 前置条件与身份边界

- 企业服务有效、套餐包含群聊（专业版及以上），入口启用。
- 第三方后端持有企业 API Key，需要查询的接口用 `read`，修改和签发凭证用 `write`。请求头 `X-TongYu-Key`，JSON 请求使用 `Content-Type: application/json`。
- Base URL：`https://chat.example.com/api/v1/open`，示例域名须替换为真实部署域名。
- `externalId` 使用第三方稳定用户 ID，1～200 UTF-8 字节；昵称最多120字。同一企业、同一入口、同一用户 ID 复用身份，不复制第三方完整用户目录。
- **第三方后端必须从登录会话读取当前用户 ID**，覆盖请求中的 `actorExternalId`、查询用 `externalId` 和签发凭证的 `externalId`。不能原样转发浏览器传入的操作者 ID。语聊验证 API Key 所属企业以及操作者的成员/群主权限；第三方后端负责用户身份真实性。
- 建群时将 `owner.externalId` 设为当前登录用户。只有第三方自身明确授权的管理流程才能代指定其他用户为初始群主。待加入用户应由第三方后端校验其存在和允许加入该群。
- API Key 仅放后端，禁止放在网页、App 包、URL 或日志中。

## 接口与权限

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| POST | `/groups` | write，建群并设置初始群主、初始成员 |
| GET | `/groups?externalId=用户ID&limit=50&offset=0` | read，只列该用户加入的第三方群，分页上限100 |
| GET | `/groups/{id}?externalId=用户ID` | read，成员查看群资料和成员列表 |
| PATCH | `/groups/{id}` | write，群主修改群名称和公告 |
| POST | `/groups/{id}/members` | write，群主按用户ID批量加人 |
| DELETE | `/groups/{id}/members/{目标用户ID}?actorExternalId=操作者ID` | write，群主移除他人，普通成员只能退出自己 |
| PUT | `/groups/{id}/owner` | write，群主转让给现有成员 |
| POST | `/groups/{id}/dissolve` | write，群主解散群 |
| POST | `/groups/{id}/member-token` | write，为已入群登录用户签发聊天凭证 |

URL 中的用户 ID 必须通过 `encodeURIComponent` 编码。群资料、转让、移除、解散接口针对第三方用户持有的客户服务群。旧客服持有的服务群仍可沿用原有加人及签发凭证接口。

## 1. 建群

```http
POST /api/v1/open/groups
X-TongYu-Key: <server-api-key>
Content-Type: application/json

{
  "inboxKey": "入口公钥",
  "externalGroupId": "order-20261012-123",
  "name": "订单沟通群",
  "owner": {"externalId": "user-1001", "displayName": "张三"},
  "members": [
    {"externalId": "user-1002", "displayName": "李四"}
  ]
}
```

成功：HTTP 201，`{"id":"群UUID","groupId":"群UUID","created":true}`。群主自动入群，不占额外客服席位，不创建 agent 账号。初始成员每次最多99人，重复用户去重。新建外部群默认容量2000人，可设置2至5000人；后续每批最多50人。旧群保持原100人容量，群主可修改。

`externalGroupId` 为第三方自己的稳定群ID（1～200字节），在同企业、同入口唯一。网络重试使用相同ID，且群主匹配时返回200、原群ID、`created:false`，不会修改原群或再次添加初始成员。群主不匹配返回409；已解散群的ID不能用来创建新群，另取新的业务群ID。

第三方应保存 `externalGroupId → groupId` 的关系。建群操作整体提交，参数或数据库错误不会产生半建成的群。

## 2. 管理群与成员

修改资料（PATCH `/groups/{id}`）：

```json
{"actorExternalId":"user-1001","name":"售后沟通群","announcement":"请在此反馈售后问题"}
```

`name`、`announcement` 可分别省略；名称1～120字，公告最多2000字，传空公告可清除公告。

加人（POST `/groups/{id}/members`）：

```json
{"actorExternalId":"user-1001","members":[{"externalId":"user-1003","displayName":"王五"}]}
```

每次1～50人；响应 `added`、`alreadyMembers`、`skipped`，每个跳过项带原因。HTTP 200 不代表每个成员均加入成功，必须检查这三组结果。已在群内的用户会更新群昵称。

转让群主（PUT `/groups/{id}/owner`）：

```json
{"actorExternalId":"user-1001","ownerExternalId":"user-1002"}
```

新群主必须已入群；转让成功后原群主变为普通成员，不能再管理群。需要指定未入群用户时，先加人再转让。

移除成员：DELETE `/groups/{id}/members/user-1003?actorExternalId=user-1002`。普通成员可将目标设为自己退出。禁止直接移除/退出群主，先转让或解散。重复移除不存在的目标可安全重试。被移除用户的旧凭证也无法继续读取或发送该群消息，其相关通话停止。

解散（POST `/groups/{id}/dissolve`）：

```json
{"actorExternalId":"user-1002"}
```

解散不可恢复，保留历史和成员关系供查询，禁止发送、加人、转让及签发新入群凭证，撤销邀请并结束通话；重复解散返回成功。成员仍可通过既有身份读取授权历史，第三方列表会返回 `dissolved:true`。第三方界面应显示确认说明和只读状态。

## 3. 网站嵌入群聊天页

后端根据当前登录用户调用 POST `/groups/{id}/member-token`，Body `{"externalId":"当前登录用户ID"}`。返回 `token`、`visitorId`、`groupId`、`expiresIn`。若用户不在群中返回404，不会自动加人。

跨域不能由第三方网页直接写语聊的 sessionStorage，使用明确来源的 postMessage 交接：

```html
<iframe id="chat" title="群聊" style="width:100%;height:600px;border:0"></iframe>
<script>
const chatOrigin = 'https://chat.example.com';
const groupId = '后端返回的群UUID';
const frame = document.getElementById('chat');
let handingOff = false;
window.addEventListener('message', async event => {
  if (event.origin !== chatOrigin || event.source !== frame.contentWindow ||
      event.data?.type !== 'tongyu.group.ready' ||
      event.data.groupId !== groupId || handingOff) return;
  handingOff = true;
  try {
    // 这是第三方自己的后端接口，需登录校验、群访问校验与CSRF防护。
    // 后端读取当前用户ID，调用member-token，不能接受任意用户ID签发。
    const res = await fetch('/api/chat/groups/' + encodeURIComponent(groupId) + '/session', {
      method: 'POST', credentials: 'same-origin'
    });
    if (!res.ok) throw new Error('获取群聊身份失败');
    const session = await res.json();
    frame.contentWindow.postMessage({
      type: 'tongyu.group.authenticate', groupId, token: session.token
    }, chatOrigin);
  } catch (error) { handingOff = false; console.error(error.message); }
});
frame.src = chatOrigin + '/groups.html?embed=1&groupId=' + encodeURIComponent(groupId) +
  '&parentOrigin=' + encodeURIComponent(location.origin);
</script>
```

群页仅接受准确 `parentOrigin` 和实际父窗口/打开窗口的消息，不支持 `*`。群页用凭证向服务端确认成员及真实聊天身份后才开始聊天；群主可在「成员」中移除成员、转让群主，在「设置」中解散群聊，成功发送 `tongyu.group.authenticated`。交接最长30秒；超时或凭证过期后，重新申请凭证并重新加载群页。凭证不要放URL或输出日志。部署需允许该第三方域名嵌入，检查反向代理的 CSP `frame-ancestors` 和 `X-Frame-Options`。

## 4. App 接入

App 建群与管理同样调用自己的业务后端，后端再调用上述开放接口。聊天可使用 WebView 加载上面的第三方嵌入页面，沿用网站交接流程；确保 WebView 允许 JavaScript、WebSocket，并按需配置麦克风/摄像头权限。聊天凭证到期或业务账号切换时，销毁旧页面及凭证，以新用户重新申请。

自研原生聊天界面可使用返回 token 调用 `/api/v1/groups/{id}/messages`、`/read` 和 `/ws/groups`，消息、分页、已读和音视频协议见 [群聊 API](groups-api.md)。成员管理通过第三方后端完成，API Key 不进入原生客户端。

## 错误与验收

福利群接口及验收规则见下文。

- 400：参数错误、新群主未入群。
- 401：密钥无效/撤销/过期或聊天凭证无效。
- 403：密钥权限或套餐不允许、用户非成员/非群主。
- 404：跨企业、群不存在、入口停用、签发对象非成员。
- 409：群已关闭、尝试移除群主、业务群ID冲突。
- 500：服务异常，可用相同业务群ID重试建群。

上线验收依次检查：用户A建群且语聊未新增客服账号 → A加用户B → B进入并双向聊天 → B不能移除A/解散 → A转让给B → A失去管理权 → B移除成员后旧凭证访问失败 → B解散后消息/通话停止 → 跨企业拒绝 → 网站跨域身份交接 → App真机登录切换与凭证续期。

## 店铺福利群（2026-10-14）

商城保留自己的买家端和店主端。后端验证店铺归属，使用该店铺对应企业的密钥。店主或有建群权限的店员创建群，owner.externalId使用已登录操作者ID。买家自愿点击邀请并确认后加入，不能把整店买家自动拉入福利群。服务端不会判断宿主的店主/买家角色：商城后端必须检查建群和管理员授权对象确实属于该店铺。

建群可增加 `maxMembers:2000`、`speakingMode:"ALL"`、`requireIdentity:true`。默认值分别为2000、ALL、true。MANAGERS表示仅群主和已授权管理员能发送新消息；普通成员仍可查看、读取、退出。模式及角色校验在消息写入事务中执行，管理员撤权后旧聊天凭证也不能发送新消息。已成功发送的消息重试仍保持幂等。

群主通过 `PUT /api/v1/open/groups/{id}/manager` 授权已入群的店员，body为 `{"actorExternalId":"店主ID","externalId":"店员ID","isManager":true}`。撤销时传false。管理员可发言和生成邀请，不能修改规则、授权管理员、转让或解散群；买家不能自授管理员权限。

群主通过 `PATCH /api/v1/open/groups/{id}/policy` 修改规则，例如 `{"actorExternalId":"店主ID","speakingMode":"MANAGERS","maxMembers":2000,"requireIdentity":true}`。字段可分别省略；容量不得小于现有成员数，已关闭群不允许修改。

群主或管理员通过 `POST /api/v1/open/groups/{id}/invite` 生成邀请，body为 `{"actorExternalId":"当前登录操作者ID"}`。返回url、ticket、expiresIn:86400；生成新邀请会撤销旧邀请。邀请票据只提供给准备邀请的用户，不输出到应用日志。

买家点商城自己的入群入口后，商城后端校验登录、邀请及用户主动加入意愿，调用 `/api/v1/open/visitor-identity` 获取该店铺入口的身份票据，再调用 `POST /api/v1/group-join/{ticket}`，body为 `{"identityToken":"身份票据"}`。响应包含token、groupId、visitorId。默认拒绝匿名入群及跨店铺身份票据；重复入群返回200，不增加人数。后续打开群使用member-token，不再依赖邀请。嵌入页面使用前述postMessage流程交接聊天token，禁止把身份票据放URL。

自有群页面提供群主规则设置、成员管理员授权及邀请生成。对应聊天身份接口为 `PATCH /api/v1/groups/{id}/policy`、`PUT /api/v1/groups/{id}/manager`（kind、id、isManager）、`POST /api/v1/groups/{id}/invite`。群详情返回speakingMode、maxMembers、requireIdentity、canInvite、canSend及成员isManager；消息刷新可用 `GET /api/v1/groups/{id}?includeMembers=false`，只返回当前成员，避免每条消息都拉取全群成员。

容量是业务上限，不代表相同人数同时在线的性能保证。自动测试覆盖超过1000人的成员关系、满员及并发最后一个名额；千人在线、多群并发、弱网重连、跨实例WebSocket送达仍需部署环境压测。大群NOTIFY收件人列表按大小拆分，避免超出PostgreSQL通知限制。音视频通话仍最多6人，群人数上限不改变会议容量。

本次代码测试覆盖后端建群、幂等重试、成员/群主权限、转让、移除后旧凭证拒绝、跨企业和解散后限制。网站跨域、App设备与生产部署应分别保留实际验收证据。
