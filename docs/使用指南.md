# 通语使用指南

第三方在自己的网站或 App 建群、指定群主、管理成员及解散群，请看 [第三方群聊接入](第三方群聊接入.md)。全程使用第三方用户 ID，无需为用户创建客服账号。

本指南对应当前本机运行的通语客服平台。先按下面的步骤完成一次客户发消息、客服接待和回复，再配置自动回复与系统接入。

## 1. 打开系统

- 管理后台：http://127.0.0.1:8080/console/
- 客户聊天入口：`{PUBLIC_BASE_URL}/h5/{inboxKey}`（在接入入口复制）
- App WebView 测试入口：`{PUBLIC_BASE_URL}/h5/{inboxKey}?source=APP`（在接入入口复制）
- 浏览器版使用指南：http://127.0.0.1:8080/console/help.html

这些地址用于这台电脑上的本地测试。手机或其他公司的系统接入时，应换成可以访问的服务器域名；手机上的 127.0.0.1 指向手机自身。

## 2. 选择正确的登录入口

后台提供两种登录方式。平台账号必须选择「平台管理员登录」；企业账号必须选择「客服工作台登录」。入口选错会提示账号或密码错误。

| 账号 | 登录入口 | 用途 |
| --- | --- | --- |
| platform | 平台管理员登录 | 开通企业、创建账号、管理企业服务配置 |
| supervisor | 客服工作台登录 | 客服主管，管理企业配置、成员、渠道与报表 |
| agent | 客服工作台登录 | 日常接待客户 |

上表用户名仅为角色示例。企业标识、实际账号与初始密码由平台管理员提供，不写入公开说明。登录后可在个人设置中修改密码。

## 3. 先完成一次聊天

1. 登录客服工作台，将个人接待状态切换为「在线」。
2. 在「企业管理 → 团队成员」中确认该客服已分配到「在线客服」入口。主管或客服主管可以编辑成员的入口分配。
3. 打开上面的客户聊天入口，发送一条测试消息。
4. 回到「收件箱」，查看「待分配」或「全部」；如果会话未分配，先接待会话。
5. 在会话中回复，客户页面应实时显示回复。
6. 接待结束后将会话标记为已解决，需要再次查看时开启已解决会话筛选。

聊天支持文字、图片和文件；更多操作包括引用回复、表情、消息操作以及客服内部备注。内部备注仅客服可见。语音录制依赖浏览器麦克风权限，目前内置浏览器未完成真实录音验收，不能据此认定录音可用。

## 4. 给其他企业开通账号

1. 使用平台账号登录，点击「开通企业与账号」。
2. 填写企业名称、企业标识和客服主管的用户名、密码，选择服务配置并提交。
3. 创建成功后保存系统显示的企业标识、登录信息和聊天入口。
4. 进入该企业详情，使用「建立账户」创建客服主管或客服坐席账号。
5. 让客服主管登录工作台，在团队成员中分配客服入口，并让客服上线。

当前版本的新账号由平台管理员创建；企业后台用于编辑已有成员及分配入口。创建失败时弹窗保留填写内容，在弹窗内提示错误，修改后可以重新提交。当前本地企业的席位上限为 4，已创建 4 个企业成员；需要更多成员时先调整企业席位。

## 5. 配置自动回复

打开「自动回复」，先选择需要配置的客服入口。各入口的配置独立。

- 关键词回复：添加匹配词、回复内容、匹配方式和优先级。
- 打开客服回复：设置客户打开聊天时看到的欢迎内容。
- 收到消息回复：设置收到客户消息后的通用回复。
- 系统客服回复：设置系统回复和离线提示。
- 智能引语：设置可点击的常见问题。
- 智能引流：设置快捷跳转入口。
- 智能菜单：配置回复、链接或转人工操作。
- 转人工客服：配置转人工规则及提示。
- 自动回复设置：启用自动回复，调整回复间隔和人工接待后的机器人行为。

每次修改后保存。若保存了规则却没有回复，先检查「自动回复设置」是否启用、是否配置了正确入口，以及会话是否已进入人工接待。这里的引导和规则功能不等于已接入大模型；真实 AI 服务仍需配置模型提供商。

## 6. 配置网页、H5 和 App 渠道

进入「渠道管理」。

- H5/App 渠道设置：修改窗口名称、服务说明，复制网页脚本、H5 地址和 App WebView 地址。
- 渠道客服：选择该入口允许接待的成员。
- 快捷方式：设置聊天中的快捷入口。
- 图文模板：设置欢迎图文和行动按钮。
- 自定义菜单：设置客户聊天底部菜单，与智能菜单共享配置。
- 用户消息列表：查看客户会话及历史消息。

当前先支持网页、H5 和 App WebView。微信等外部渠道尚未接入；原生 Android/iOS 设备上的完整功能还需要单独验收。

## 7. 如何接入别人的系统，Token 怎么用

### 匿名客户接入

在「应用接入」或「渠道管理」复制生成的嵌入脚本，放到对方网站中。匿名客户只需要服务地址和入口标识，不需要将服务端密钥交给浏览器。

```html
<script>
window.RelayDeskSettings = {
  endpoint: 'http://127.0.0.1:8080',
  inboxKey: '<从接入入口复制的 inboxKey>'
};
</script>
<script src="http://127.0.0.1:8080/widget.js"></script>
```

H5 可以直接打开聊天链接；App 可用 WebView 加载渠道设置中复制的 App 地址。实际部署时替换上面的本机地址。

### 对接已有登录用户

1. 在「应用接入 → 服务端密钥」创建具有对应入口权限的密钥。
2. 对方系统的后端根据自己的登录用户，调用 `POST /api/v1/open/visitor-identity`。
3. 请求头使用 `X-RelayDesk-Key`；请求体提供 `inboxKey`、真实用户的 `externalId` 和 `displayName`。
4. 将响应中的 `identityToken` 和 `inboxKey` 返回给对方前端。
5. 前端把 `identityToken` 加到 `window.RelayDeskSettings`，再加载组件。

服务端密钥保存在对方后端。`identityToken` 是短期客户身份票据，有效期 5 分钟；聊天组件会自行换取会话和实时连接凭证。后台登录 token、服务端密钥和客户身份票据用途不同，不能互换。不要把身份票据拼进 H5 链接。

完整请求、iframe 身份通信和事件回调配置见项目中的 `docs/saas-onboarding.md`、`docs/integrations.md`、`docs/open-api.md`。

## 8. 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 账号密码错误 | 检查平台/客服登录入口、用户名、密码和企业标识 |
| 客户发了消息，客服看不到 | 确认双方使用同一入口；查看全部或待接待；检查成员入口分配、在线状态和筛选条件 |
| 客服回复后客户收不到 | 确认回复的是当前客户会话，刷新重连；检查服务和 WebSocket 连接 |
| 创建账号提示重复 | 在弹窗里修改用户名后重试，无需重新填写其他内容 |
| 无法继续创建客服 | 检查企业席位上限和已有成员数 |
| 自动回复没有触发 | 检查入口选择、总开关、规则条件、回复间隔和人工接待状态 |
| 手机打不开本地链接 | 使用手机可访问的电脑局域网地址或部署域名，不能使用手机自己的 127.0.0.1 |
| 麦克风没有权限提示 | 换用支持录音权限的浏览器，并检查站点权限；当前内置浏览器录音验收受限 |

## 9. 本机服务如何重新启动

当前使用 Docker 容器 `relaydesk-local` 和数据库容器 `deploy-postgres-1`。打开 Docker Desktop 后，在 PowerShell 执行：

```powershell
docker start deploy-postgres-1
docker start relaydesk-local
Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing
```

健康检查返回 200 后，打开后台地址。首次安装和服务器部署请另看 README 与部署文档；这里的启动命令用于当前已经配置好的本机环境。

## 会话分配与搜索

「我的会话」显示分配给自己的会话；「待分配」显示还没有接待人的会话；「全部」显示当前权限和客服入口下的会话。自动分配要求入口开启自动分配，客服上线且具有入口接待权限，并满足接待容量。

在未分配会话顶部点击「开始接待」可领取会话；点击客服图标「分配给客服」可指定接待人。已分配会话的同一位置显示「转派客服」。选择目标客服并填写内部交接说明后确认分配。

后台列表搜索匹配客户名称、会话主题和未撤回的历史消息，结果遵守当前分配、入口及已解决筛选条件。客户聊天顶部的搜索只查询当前会话；输入关键词可自动搜索，按回车立即查找。点击已加载消息的结果可定位原消息。

## 群聊

后台新增「群聊」。点击「建群」，选择内部协作群或客户服务群，填写群名称；客户服务群还需选择客服入口。

- 群成员：群主可添加同企业同事、移除成员。内部协作群不允许客户加入。
- 邀请客户：客户服务群的群主点击「邀请客户」，复制链接；客户填写称呼加入，无需邮箱或验证码。邀请24小时有效，重新生成会撤销旧邀请。
- 用本站用户建群：业务后端调用开放 API，按本站用户 ID（`externalId`）批量加入服务群，前端再换群聊会话打开页面；与一对一登录客户共用同一访客身份，详见 [开放 API](open-api.md) 与 [群聊 API](groups-api.md)。
- 群消息：群成员可发送文字、表情字符、搜索群消息，实时接收消息；未读数量按成员分别保存。
- 群设置：群主修改名称、公告和归档状态。归档保留历史并停止发消息和客户加入。
- 客户页面：可查看成员和公告、发消息、搜索、加载历史、退出群聊；群身份仅保存在当前浏览器会话。

当前群聊首版提供上述文字协作能力。图片文件、单独的@提醒、群管理员角色与多人音视频尚未接入群聊，不能将一对一聊天中的相应能力视为已经支持群聊。


### 群聊里的昵称、撤回、解散与语音

- 发送：打开内部协作群或客户服务群，在底部输入文字后发送。
- 撤回：自己的消息下面点「撤回」，双方显示「该消息已被撤回」，搜索不再显示原文。
- 群昵称：客服点群聊右上角「更多群聊操作 → 我的群昵称」；客户点「设置 → 保存昵称」。只改变此群以后消息的称呼，不改变登录账号。
- 建群：客服工作台「群聊 → 建群」，选择内部协作或客户服务。
- 解散：群主点「更多群聊操作 → 解散群聊」。确认前会解释影响，解散后保留历史，停止发送和通话，所有邀请失效。
- 语音：客服点群聊右上角电话图标，客户点「通话」，选择群成员发起一对一语音。客服任意工作台页面都可收到来电提示，打开通话页后接听；客户直接在群页面接听。接听时允许麦克风，可静音、拒接、挂断。

麦克风授权失败可再次接听；跨网络通话需要 HTTPS 和 STUN/TURN 配置，详见 [群聊 API 与通话接入](groups-api.md)。本次本地浏览器的真实麦克风/双向音频结果以验收报告为准，信令接听成功不能替代实际听音验证。


## 16. 群语音与群视频通话

1. 客服进入「群聊」，选择内部协作群或客户服务群，点击右上角「语音与视频通话」。客户在群聊页面点击「通话」。
2. 选择「群语音通话」或「群视频通话」。一场最多 6 人，其他成员打开同群后可点「加入通话」。客服工作台也会提示新发起的群通话。
3. 不想开启摄像头时，取消勾选「视频通话时开启我的摄像头」，仍可加入视频房间并参与语音。点击「开启摄像头」时才申请摄像头权限。
4. 通话面板显示每位成员的连接、麦克风和摄像头状态。可静音、取消静音、开关摄像头或退出。发起人和群主可「结束所有人通话」。
5. 退出后释放本机设备；其他人继续通话。最后一人退出则结束全场。群解散、归档或成员被移出也会停止对应通话。

平台管理员入口：`http://127.0.0.1:8080/console/?surface=platform`。客服入口：`http://127.0.0.1:8080/console/?surface=agent`。入口分别按标签页保存，已有有效平台登录会恢复运营后台，避免被其他客服标签页的入口偏好覆盖。

本轮本地验收：三人真实群语音已通过；视频房间三人关闭摄像头加入已通过。按用户选择没有启用摄像头，真实视频画面收发尚未验收。跨公网 TURN、原生 App 和物理手机未在本机浏览器验收范围。


## 17. 新消息提醒与未读 / 已读接入

客服进入「设置」，页面底部可切换新消息提示音、测试提示音和桌面通知。提示音默认开启；桌面通知默认关闭，需要主动开启并允许浏览器通知。拒绝或不支持通知时不会影响收件箱角标。网页关闭后不再提醒，原生 App 推送需另行接入。

公开客服回复的气泡区分未读、已送达和已读。页面在前台并查看会话时才上报已读；停留在设置页、收起访客聊天组件、浏览器页面隐藏或客服正在查看历史消息时，不自动清空最新未读。只读到某条消息时，后续消息仍未读。

接入方后端用 API Key 查询 `/api/v1/open/unread` 和 `/api/v1/open/conversations/{id}/receipts`；上报使用相同会话路径下的 `/read`、`/delivered`，Body 必须包含 readerType、readerId、正数 sequence。详情见 [开放 API 与回执接入](open-api.md)。客户自己的角标按该客户有权访问的会话汇总，不可直接显示企业未读总数。

客服主管在「接入 → 事件回调」选择 conversation.read、conversation.delivered。已有回调需要补选新事件。接收方验证 HMAC 签名并按投递 ID 去重，处理完成后返回 2xx。回调地址支持 HTTP/HTTPS，正式环境推荐 HTTPS；表单校验或保存失败时保留输入，可直接修正重试。

## 企业角色简化

企业侧仅有客服主管（SUPERVISOR）和客服坐席（AGENT）。主管管理企业配置、已有成员、渠道、知识库、自动回复与报表；坐席在已分配入口中接待客户。新账号仍由平台超级管理员创建，额度也由平台超级管理员分配。旧 OWNER/ADMIN 在升级时迁移为主管并注销旧登录，至少保留一名启用主管。平台角色与第三方群主身份不受影响。
