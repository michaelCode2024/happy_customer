# 平台交付能力与文档缺口审查

审查日期：2026-10-23。依据本地 Go/Flutter/Widget 源码、SQL migrations、容器模板、现有客户资料及历史文档。R3 额外执行一次无凭证的现网 `GET /api/v1/open/me`，仅核对错误响应中的鉴权头名称；没有登录线上、执行认证业务 API、验证支付、测试安全渗透或进行客户真机/E2E 验收。

## 当前结论

产品具备可运营多租户客服平台的主要业务基础，可以在一个运营方实例中创建多个企业租户，并为企业分配成员、入口、套餐、额度及服务期限。现阶段应表述为“多租户客服 SaaS 基础平台”，不应宣传为“已完成可独立销售、自助付费、可任意客户一键安装的成熟 SaaS 商业套件”。

当前产品客户（如 caizhan）是平台上的单个企业租户，包含其自身的客服入口；这不是独立部署或授予客户运营下游租户的 SaaS 平台许可。将平台交付给另一名运营方属于单独的商业许可与发行交付。

## 能够由代码支持的能力

- 平台和企业采用不同登录/角色；平台 SUPER_ADMIN 写入、平台 ADMIN 只读；租户角色为 SUPERVISOR/AGENT。
- 企业创建会初始化租户、主管、默认入口、路由/AI 设置和试用订阅；套餐本身提供服务端 feature gate。
- 当前计划名为 TRIAL、STARTER、GROWTH、ENTERPRISE。默认坐席/月消息额度分别为 2/1,000、1/5,000、3/50,000、10/1,000,000；试用开通默认为 14 天。
- AI 月额度新开通默认 Growth 5,000、Enterprise 100,000；管理员可在额度接口自定义数量。不是所有 Enterprise 功能“全开放”，应查看 feature gate。
- 管理员可通过带 requestId 和版本的事务化额度 API 手工配置服务期及追加消息/AI 额度、保留审计；没有支付、订单、自动扣款或续费服务。
- 访客、客服、入口与租户资源由后端核对归属；消息序列、幂等、断线补拉、群聊和 Webhook 均已有实现，但实际客户环境仍须独立验收。
- 迁移自动在服务启动时执行并用 schema_migration 避免重复；它不提供向下迁移或升级后自动回滚。

## 交付优先级

### 上线发客户前必须完成

1. **发行安装物**：当前通用 Dockerfile 只构建 Go，预先要求 Widget dist 和 Flutter Web；现有 isolated 脚本含特定服务器地址、18080 固定端口、DEMO 默认 true 和测试管理员回退值。需产出固定 digest 的镜像、生产安全配置模板和客户安装向导。
2. **真正从零安装验收**：在干净 Linux 环境验证首次管理员、迁移、业务静态资源、Widget/H5、HTTPS、WebSocket、Origin/CSP 和附件；验证关闭演示与默认账号。
3. **备份/恢复演练**：数据库与附件配对、加密、异地保管、明确 RPO/RTO，在隔离环境恢复后跑真实消息和附件业务。
4. **目标客户端到端验收**：管理员/企业/坐席权限、多租户越权拒绝、客户身份签发、入口授权、重试、Webhook、服务到期与账号撤销按产品链路验证。
5. **独立平台代理授权**：书面确定允许的运行实例、租户规模、使用范围、版本升级、停服/导出和二级支持。当前套餐不是软件许可/转授权开关。
6. **首次改密流程**：当前登录响应、成员数据和前端没有首次登录或管理员重置后的改密标记与阻断。已有手动改密接口与 Flutter 设置入口，但这不等于自动提醒或强制改密；上线交付应明确是否补齐，并分别覆盖创建、重置、会话恢复与各端界面。

### 商业化上线前必须决策/开发

- 在线购买、订单、支付通知验签、对账、退款、续费和付款失败后状态转移。目前平台管理员手工开通及调额度，不得称为客户自助订阅。
- 账单/税务、服务周期时区、通知提醒和失败补偿；此项属于产品商业链路，不是改显示文案可解决。
- 数据导出、注销/删除、法定留存、附件清理和消息期限。当前会话历史没有按套餐自动清理，不能因此承诺永久保留。
- 附件安全审查、空间限额和对象存储成本控制；上传大小/MIME 校验不等于完整恶意内容检测和计费。
- 实例监控告警、集中日志脱敏、关键操作追踪、恢复/升级演练记录与明确支持时段。
- 多副本生产验证：速率限制目前是进程内状态，跨实例业务需重新验证 LISTEN/NOTIFY、后台 worker、连接上限、附件一致性与并发性能。

## 已更正的高风险不一致

- 开发数据中的问答错误宣称各套餐坐席量、独立部署、全量 AI 能力、自动试用注册/付款和原生 SDK；已改为与现行限额、手工开通和实际接入模型相符的描述。
- 旧 `docs/deployment.md` 是带历史云平台价格/日期和未部署状态的免费选项研究；移入 `docs/历史资料`，新增按 Compose、镜像静态输入、生产配置、升级/恢复写作的正式部署指南。
- `docs/api.md` 原称“当前开发版”且写入固定 localhost/ws 地址；已改为目标实例占位与 HTTPS/WSS 说明。
- 群聊文档原鼓励把 identityToken 放入查询参数并写入宿主 sessionStorage；已改为不含秘密的 URL 与精确来源 postMessage 会话交接。应在上线客户构建实测该桥接。
- 企业停用状态与订阅额度状态是不同对象；API 文档中混用 `SUSPENDED` 的示例已纠正。
- 2026-10-11 网页验收等记录保留到历史资料并标注原始证据时间，不当作当前证据。
- 彩站现网接口无凭证 GET 返回 401 / API_KEY_REQUIRED，并明确要求 X-RelayDesk-Key；R3 据此填写客户鉴权头。仓库源码使用 X-TongYu-Key，通用指南改为以客户配置单列明的头名称调用，避免混用协议版本。原开通记录中的账号、初始密码和密钥保留在现行专属文件中；有效性尚未通过登录或认证 API 验证。被替代的凭证原件与旧对外文档已经删除。
- 使用指南及 Open API 中“网页关闭后不再提醒”、群管理员和多人通话未实现的旧说法已更正。当前源码包含 Web Push、群管理及最多六人 mesh 通话；后台送达和真实设备体验仍须单独验证。商城/Flutter 的历史本机联调章节已提取到历史目录。
- 客户档案、模板和生成记录移到 docs/交付管理；对外目录只存正式资料及当前资料包。客户正式文件直接位于其独立目录，不再混入内部记录。通用与客户资料均有完整白名单；脚本检查不替代凭证有效性与目标实例业务验收。

## 后续商业交付验收闸门

只有完成发行镜像签名/校验、非特权运行、无默认秘密和公开数据库端口、固定版本依赖与 SBOM、漏洞处理流程、首次管理员安全设置、密钥轮换、可重复安装/升级/恢复、租户隔离攻防测试、数据权利与支持合同后，才可将“可独立销售并运营的多租户 SaaS 平台”标注为已交付。以上未在本轮擅自扩大为新业务功能开发。
