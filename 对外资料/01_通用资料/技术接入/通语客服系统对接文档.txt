通语客服系统对接文档
版本：1.0　日期：2026-10-14
适用：网站、H5、Flutter/App、商城买家端、店主端及业务后端。

一、接入准备

由客服系统管理员向开发方提供：
1. BASE_URL：客服系统 HTTPS 根地址，不带末尾斜杠。
2. inboxKey：已开通的客服入口标识。
3. 租户 API Key：服务端调用凭证，身份签发需要 write 权限及相应套餐能力。
4. 网站宿主 Origin：例如 https://app.example.com，包含协议、域名与非默认端口，不带路径。
5. 如需商城店铺自动开通，单独提供商城 API Key。

本文所有 example.com 地址、用户编号与凭证均为示例。实际域名、入口和套餐须使用管理员提供的开通配置。
API Key 只配置在业务后端；不得写入网页、Flutter 构建参数、App 安装包、URL 或日志。
inboxKey 是公开入口标识，不是密钥；identityToken 是短期身份票据，不是聊天接口的 Bearer Token。
普通租户密钥使用 X-RelayDesk-Key，商城密钥使用 X-RelayDesk-Marketplace-Key，两者不可互换。

二、推荐接入流程

1. 用户在原业务系统登录。
2. 用户点击客服，客户端请求自己的业务后端。
3. 业务后端从已验证的登录会话取得用户 ID 和昵称，调用通语签发身份票据。
4. 业务后端向客户端返回 h5Url、identityToken、expiresIn。
5. 客户端加载客服页面，通过 authenticate 指令交接身份。
6. 客服页面负责聊天、附件、未读、已读、重连和历史消息。

同一个 inbox 下，稳定 externalId 用于识别同一业务客户。不要使用昵称、随机数或设备号替代正式用户 ID。
匿名咨询可直接打开 /h5/{inboxKey}，不传 externalId。需要绑定登录客户时必须由后端签发票据。

三、后端签发登录客户身份

POST {BASE_URL}/api/v1/open/visitor-identity
请求头：
X-RelayDesk-Key: <SERVER_API_KEY>
Content-Type: application/json

请求体：
{
  "inboxKey": "your-inbox-key",
  "externalId": "user-1001",
  "displayName": "张三"
}

字段说明：
inboxKey：必填，必须属于密钥对应企业。
externalId：必填，使用业务系统稳定 ID。长度最多为 200 个 UTF-8 字节，建议使用短 ASCII ID。
displayName：客户显示昵称，可省略。

成功响应 HTTP 200：
{
  "identityToken": "<SHORT_LIVED_IDENTITY_TOKEN>",
  "expiresIn": 300,
  "inboxKey": "your-inbox-key"
}

票据有效期 300 秒。建议每次打开客服时获取新票据；不要将票据放入 URL、浏览器历史或持久化存储。
业务后端应设置 Cache-Control: no-store，并只对当前已登录用户返回其自身身份票据。
禁止直接采信客户端提交的 externalId，以免用户冒用其他客户身份。

建议自行实现的宿主业务接口（不是通语现有接口）：
GET /api/customer-service/session
响应示例：
{
  "h5Url": "https://chat.example.com/h5/your-inbox-key?source=APP",
  "identityToken": "<SHORT_LIVED_IDENTITY_TOKEN>",
  "expiresIn": 300
}

四、网站和 H5 嵌入示例

下例由网站自己的后端提供 /api/customer-service/session。
将 chat.example.com 与入口替换为实际配置。parentOrigin 必须是宿主精确 Origin；使用 * 时无法交接登录身份。

<iframe id="relaydesk" title="在线客服"
  allow="microphone; camera; clipboard-write"
  style="width:100%;height:650px;border:0"></iframe>

<script>
(async () => {
  const chatOrigin = 'https://chat.example.com';
  const frame = document.getElementById('relaydesk');
  const response = await fetch('/api/customer-service/session', {
    credentials: 'same-origin', cache: 'no-store'
  });
  if (!response.ok) throw new Error('获取客服身份失败');
  const session = await response.json();
  const url = new URL(session.h5Url);
  if (url.origin !== chatOrigin) throw new Error('客服地址不匹配');
  url.searchParams.set('parentOrigin', location.origin);
  const authenticate = () => frame.contentWindow.postMessage({
    type: 'authenticate', identityToken: session.identityToken
  }, chatOrigin);
  window.addEventListener('message', event => {
    if (event.origin !== chatOrigin || event.source !== frame.contentWindow) return;
    let data = event.data;
    if (typeof data === 'string') {
      try { data = JSON.parse(data); } catch { return; }
    }
    if (!data || data.source !== 'relaydesk') return;
    if (data.type === 'close') {
      // 在这里隐藏客服容器或返回业务页面。
    }
    if (data.type === 'error') {
      // 展示错误并根据错误类型决定是否重新向业务后端取票据。
    }
  });
  frame.onload = authenticate;
  frame.src = url.toString();
})().catch(() => {
  // 展示“客服暂时不可用，请稍后重试”，不要输出凭证。
});
</script>

宿主可发送的指令：
打开：{ "type": "open" }
关闭：{ "type": "close" }
预填文字：{ "type": "prefill", "content": "我想咨询订单" }
发送文字：{ "type": "say", "content": "你好" }
交接身份：{ "type": "authenticate", "identityToken": "<TOKEN>" }
say 会实际发送消息，请只在用户明确触发时使用，并等待聊天身份初始化完成。

页面回传事件格式：
{ "source": "relaydesk", "type": "close" }
其他事件包括 ready、open、message、sent、unread、resize、error，data 随事件变化。
HTTP iframe 跨域策略、服务端 FRAME_ANCESTORS、ALLOWED_ORIGINS 和实际页面来源必须配套配置。

五、Flutter / App 接入

推荐复用完整 /h5/{inboxKey}?source=APP 页面，通过 WebView 承载。
匿名客服可直接加载；登录客户先向业务后端获取票据。

Flutter Web：使用第四节 iframe 方案，parentOrigin 为 Flutter 网站实际 Origin。
Android/iOS WebView：需要配置原生桥，将指令送至组件 bridge.onMessage，并通过 bridge.postMessage 接收 JSON 事件。
原生 WebView 没有 iframe 父窗口，不能直接照搬 iframe.contentWindow.postMessage。
桥接协议为上述 authenticate、close 等 JSON；具体注入方式需按项目所用 WebView 插件和页面适配器实现。
接入方应根据所用 WebView 插件完成原生消息桥适配，并验证身份交接和页面返回。

App 收到 source=relaydesk、type=close 时返回上一业务页面。
用户退出或切换账号时销毁旧客服页面及身份，重新获取当前用户票据，避免复用上一个客户的聊天状态。
录音和拍照需要系统权限及 WebView 权限回调；线上使用 HTTPS。附件、键盘遮挡、安全区、返回按钮需真机验收。

六、商城店铺与店员接入（按需启用）

商城密钥由平台管理员创建商城时签发。以下请求均由商城后端发起：
X-RelayDesk-Marketplace-Key: <MARKETPLACE_SERVER_KEY>
Content-Type: application/json

1. 创建或更新店铺
PUT /api/v1/marketplace/shops/{shopId}
{ "name": "店铺A", "status": "ACTIVE" }
返回 shopId、tenantId、inboxId、inboxKey、created、status。
shopId 使用商城稳定 ID；重复请求复用店铺映射。status 可为 SUSPENDED。

2. 创建或更新店员
PUT /api/v1/marketplace/shops/{shopId}/staff/{staffId}
{ "displayName": "店员A", "role": "AGENT", "status": "ACTIVE" }
店主或主管使用 SUPERVISOR，普通客服使用 AGENT；停用使用 DISABLED。
创建或恢复受套餐席位限制；角色变更或停用会撤销旧会话。

3. 店员登录会话
POST /api/v1/marketplace/shops/{shopId}/staff-session
{ "externalId": "staff-1001" }
返回 token、agent、tenantId、inboxId、expiresIn。
业务后端验证操作者和店铺归属后签发；前端使用真实店员 token 访问 console 接口。
登录不会自动上线，应通过工作台在线状态与领取会话流程完成接待。
需要复用 /console/?embedded=1 时，应对接工作台专用身份桥，不能把访客 identityToken 当店员 token。

4. 买家登录会话
POST /api/v1/marketplace/buyer-session
{ "externalId": "buyer-1001", "displayName": "买家A" }
返回 token、expiresIn:3600。

以下由买家客户端使用 Authorization: Bearer <BUYER_TOKEN>：
GET /api/v1/marketplace/buyer/threads?limit=50&offset=0
查询跨店铺私聊与已加入群聊，返回 items、total、unread、limit、offset。
items 中 kind 为 CONVERSATION 或 GROUP；total、unread 是全量值。

POST /api/v1/marketplace/buyer/shops/{shopId}/session
返回 token、identityToken、inboxKey、visitorId、tenantId、shopId。
嵌入完整聊天页面使用 identityToken；自研聊天接口使用返回的 widget token。

实时列表通知：/ws/marketplace?token=<BUYER_TOKEN>。
收到 conversation.updated 或 group.updated 后重新获取列表；断线恢复后补拉。
POST /api/v1/marketplace/buyer/logout 撤销当前买家会话及绑定聊天、群会话；其他设备不受影响。

七、福利群接入（按需启用）

商城后端 Base：/api/v1/marketplace/shops/{shopId}/groups
POST Base：建群。
POST /{id}/members：批量加入成员。
POST /{id}/invite：生成邀请。
PUT /{id}/manager：设置管理员。
PATCH /{id}/policy：设置容量和发言规则。
GET Base、GET /{id}：列表与详情。
PUT /{id}/owner：转让群主。
DELETE /{id}/members/{externalId}：移除或退出。
POST /{id}/dissolve：解散群。
群管理接口的完整请求字段与响应格式由技术支持提供专项接口说明。

福利群群主和新授权管理员必须是本店有效店主或店员。买家应主动确认加入。
买家用买家 token 调用 POST /api/v1/marketplace/buyer/groups/{id}/session。
店员用客服 token 调用 POST /api/v1/marketplace/staff/groups/{id}/session。
返回 token、groupId、visitorId、expiresIn:3600，使用群会话 token 访问群消息接口。
群页面 /groups.html?groupId=<ID>&embed=1&parentOrigin=<精确宿主Origin>。
父页交接：{ "type": "relaydesk.group.authenticate", "groupId": "<ID>", "token": "<GROUP_TOKEN>" }。
群会话与访客票据不可混用。

八、商品与订单卡片（按需启用）

商城后端调用：
POST /api/v1/marketplace/shops/{shopId}/conversations/{id}/cards
{
  "senderType": "VISITOR",
  "externalId": "buyer-1001",
  "clientMessageId": "<UUID>",
  "card": {
    "kind": "ORDER",
    "id": "order-1001",
    "title": "商品名称",
    "amountMinor": 29900,
    "currency": "CNY",
    "orderNumber": "ORDER1001",
    "status": "待发货"
  }
}

senderType 为 VISITOR 或 AGENT；AGENT 回复需先领取接待。
kind 为 PRODUCT 或 ORDER；ORDER 必须有 orderNumber。
title 为 1～120 字；amountMinor 为非负整数，最大 9007199254740991，按两位小数最小货币单位解释。
29900 表示 299.00。currency 为三位大写币种。url、imageUrl 可省略，仅允许 http/https 且禁止 URL 用户信息。
业务后端从自己的数据库取得权威金额、订单状态并校验归属，不采信客户端传来的价格和状态。
卡片保存发送时快照；后续订单变化需发送新卡片。不要包含地址、支付凭据等敏感内容。
网络重试复用同一 clientMessageId。
群卡片接口为 POST /api/v1/marketplace/shops/{shopId}/groups/{id}/cards，字段 externalId、clientMessageId、card。
分享订单额外传 shareOrder:true，并由业务后端确认允许向该群分享。

九、开放 API 与消息同步

普通租户后端使用 X-RelayDesk-Key：
GET /api/v1/open/me：检查当前租户与密钥。
GET /api/v1/open/conversations：会话列表。
GET /api/v1/open/conversations/{id}：会话详情。
GET /api/v1/open/conversations/{id}/messages：历史消息，支持 after / before。
POST /api/v1/open/conversations/{id}/messages：客服侧代发消息。
GET /api/v1/open/visitors：访客列表。
GET /api/v1/open/agents：客服列表。
GET /api/v1/open/stats：企业统计。
GET /api/v1/open/unread：企业未读汇总，不可直接作为单个客户未读。
GET /api/v1/open/conversations/{id}/receipts：权威已读与送达游标。
POST /api/v1/open/conversations/{id}/read：用户实际查看后上报已读。
POST /api/v1/open/conversations/{id}/delivered：设备收到后上报送达。

回执请求体：
{ "readerType": "VISITOR", "readerId": "<VISITOR_UUID>", "sequence": 12 }
sequence 必须大于 0；游标只前进。后端验证 readerId 与当前用户、会话的关联。
收到实时通知不等于已读；消息按 sequence 排序，断线后按 after 补拉。
完整聊天页面已承担这些同步职责；自研聊天时需自行实现。

十、Webhook（按需启用）

管理员配置回调地址、密钥及订阅事件，如 message.created、message.agent、conversation.read、conversation.delivered。
请求头：X-RelayDesk-Event、X-RelayDesk-Delivery、X-RelayDesk-Timestamp、X-RelayDesk-Signature。
签名原文：<timestamp>.<原始请求体>。
算法：HMAC-SHA256；签名头格式 sha256=<十六进制签名>。
使用原始请求体字节验签，采用常量时间比较，检查时间窗口，并按投递 ID 幂等。
成功持久化后返回 2xx；失败会重试。游标回调取最大 sequence，防止乱序回退。

十一、错误处理

错误响应结构：
{ "status": 401, "code": "...", "message": "...", "timestamp": "..." }
部分错误可能没有 code，处理时结合 HTTP 状态与 message。
400：参数无效，修正参数。
401：凭证缺失、无效或过期，重新获取对应凭证。
403：权限或套餐能力不足，检查开通配置。
404：资源不存在或不属于当前企业/用户，检查映射与归属。
5xx 或网络失败：保留当前状态并有限重试；发送消息重试保持 clientMessageId。
IDENTITY_TOKEN_REQUIRED：使用后端身份票据，不直接传 externalId。
API_KEY_REQUIRED / API_KEY_INVALID：检查服务端密钥配置。
禁止无限重试、将错误响应当成功，或在日志中输出完整凭证。

十二、开发分工与验收

客服系统管理员：开通企业、入口、客服、套餐与密钥，配置域名策略和 Webhook。
业务后端：验证原登录、签发短期身份、校验用户/店铺/订单归属，保管密钥。
网站/App：加载页面、交接身份、处理关闭事件、权限与账号切换。

上线前逐项验证：
1. 当前用户能发消息，客服能回复，刷新后历史保持一致。
2. 账号 A 切换账号 B 后无法看到 A 的历史；同账号重新登录保持正确身份。
3. 过期票据能重新获取；错误入口、错误企业与越权用户访问被拒绝。
4. 断网重连补回消息，重试不产生重复消息，未读与已读符合实际查看行为。
5. 图片、附件、录音与返回按钮按目标浏览器和真机验证。
6. 商城买家、店铺、店员数据隔离；停用、退出、群权限与卡片订单归属生效。
7. 检查前端安装包、URL、浏览器存储及日志不含服务端密钥。
8. 在正式接入地址完成身份、消息、权限和目标设备的全流程验收。
